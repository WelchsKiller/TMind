1. ECG 암호화 — 제안대로 진행

회신: 제안해 주신 Hybrid Encryption 스펙을 그대로 수용하였으며, 앱에 반영 준비를 완료했습니다.

■ 확정 이해
  - 데이터 암호화: AES-256-GCM (IV 12byte, Auth Tag 16byte)
  - CEK 암호화: RSA-OAEP-256 (SHA-256, RSA 3072bit)
  - 인코딩: 전 필드 Base64URL
  - 헤더 JWT 포함
  - 공개키: 서버 API 조회 방식
  - 업로드 시 keyId 함께 전송
  - 분할 없이 1회 multipart 전송

■ 앱 구현 현황
  - EcgUploadCrypto 유틸리티 구현 완료 (AES-256-GCM + RSA-OAEP-256)
  - 공개키 조회 API 연동 준비: GET /api/member/crypto/public-key (keyId, publicKey)
  - 공개키 캐시 후 HRV 업로드 signal 파트를 암호화 JSON으로 전송
  - data 파트 JSON에 keyId 필드 포함
  - 공개키 API 미배포·조회 실패 시: 평문 CSV 업로드로 폴백 (전환 기간)

■ 요청
  - 엔드포인트 경로·응답 형식·keyId 규격 확정 시 알려주시면 즉시 연동 테스트하겠습니다.


2. ECG 전송 데이터 범위 — 원본 전체 전송 확정

회신: 원본 전체(5분 / 250Hz / 약 75,000 샘플) 전송이 가능하며, 앱을 해당 방식으로 수정했습니다.

■ 변경 내용
  - 기존: 분석 후 대표 파형(lastSpike, 100~500 샘플)만 CSV 업로드
  - 변경: 측정 중 EcgCapture에 누적된 5분 원시 신호 전체를 CSV(index,value)로 업로드
  - 용량: CSV 약 0.8~1.5MB, 암호화 JSON 적용 시 약 1~2.5MB 예상

■ 전제 확인
  - 서버는 bpm·hrvMs·measurementValid를 재판정하지 않고 그대로 저장
  - 신호 유효성 판정 주체는 앱 — 동일하게 유지
  - measurementValid=true인 유효 측정만 uploadHrv 호출

■ 암호화 용량
  - 원본 전체 전송 확정에 따라 암호화 스펙·multipart 크기 제한(5MB 이상)을 위 기준으로 반영해 주시면 됩니다.


3. 오늘의 화면(/today) — participatedDays / studyDayIndex 확인

회신: participatedDays가 필요합니다. studyDayIndex는 선택 사항입니다.

■ participatedDays — 필요 (필수에 가까움)
  - 용도: 「7일 정서 추이」 버튼 노출 조건
  - 조건: participatedDays >= 7 일 때 버튼 표시
  - 현재: GET /api/member/participation 의 period.participatedDays 사용 중
  - 요청: /today 응답에 participatedDays 포함 시 participation API 호출 없이 동기화 가능

■ participatedDays 의미 (앱 이해)
  - 참여 기간 중 세션을 끝까지 완료(피드백 제출까지)한 날의 수
  - 참여현황 API의 participatedDays와 동일한 값인지 확인 요청드렸던 내용 → 서버 설명과 일치하는 것으로 이해

■ studyDayIndex — 불필요 (우선)
  - 앱 UI에서 연구 N일차 표시·별(7일) 계산은 로컬 연구 시작일 기준으로 처리 중
  - 서버 studyDayIndex 제공 시 향후 동기화 검토 가능

■ 기타 /today 필드
  - missedType: 수신 시 대시보드 인사 문구에 반영하도록 UI 추가 완료
  - eventGuideText: eventActive=true일 때만 값 수신 — 현재와 동일 이해
  - 서버 기준 오늘 날짜(serverDate): 수신 시 자정 경계 동기화에 활용 예정 (모델 준비 완료)

  - AM 세션 중 12시 경과 후 재진입 시 PM으로 전환, 이전 AM 세션은 이어하지 않음 — 동의

5. POST /api/member/session 호출 시점 — 순서 반영

회신: 이전 답변서의 「HRV 없이 EMA/일기 진입 시 세션 시작」 기술을 수정·반영했습니다.

■ 세션 시작 시점 (수정 후)
  - 정규 세션(AM/PM): 심박변이도 결과 확정(HrvResultActivity 확인) 또는 건너뛰기(HrvGuideActivity) 시
  - 이벤트 세션: 「추가 측정」 진입 시 isEvent=true 로 1회 생성
  - EMA·음성일기 화면 진입 시에는 세션 시작 API를 호출하지 않음 (기존 sessionId 재사용)

■ 미션 순서 (서버 검증과 동일)
  - 심박변이도 → 마음상태 설문 → 마음일기
  - HRV 없이 EMA/일기 진입 시 서버 오류 방지를 위해 앱에서 선행 단계 미완료 시 진입 차단

■ HRV 건너뛰기
  - HrvGuide 「건너뛰기」: POST /api/member/session → POST .../hrv/skip (skipReason: USER_SKIP) → EMA 진입
  - skipReason 필수 — USER_SKIP 전송


6. 음성일기 — MIME 타입 확인

회신: 아래와 같습니다.

■ 녹음 스펙 (변경 없음)
  - 최대 180초(3분)
  - MPEG-4 / AAC, 16kHz, 64kbps
  - 최대 약 1.4MB

■ 업로드 파일
  - 확장자: .m4a
  - MIME 타입: audio/mp4

  - Content-Type: audio/mp4 (업로드 코드 반영 완료)

8. 이전 응답 / 이전 분석결과 조회 — 현황

회신: 현재 앱은 로컬 히스토리로 처리 중이며, 서버 API 없이도 기본 조회 기능은 동작합니다.

■ 현재 앱 구현 (로컬)
  - HistoryStore (SharedPreferences + AES 로컬 저장)
  - 「이전 설문」: HistoryListActivity (MODE_SURVEY) — EMA 응답·세션·시각·문항별 답
  - 「이전 분석결과」: HistoryListActivity (MODE_ANALYSIS) — HRV·예측 valence/arousal·시각
  - SurveyDetailActivity: 설문 상세(전체 문항·응답)
  - WeeklyTrendActivity: 최근 7일 일별 분석 요약 (로컬)

■ 서버 API 필요 여부
  - 단말 교체·재설치·다기기 동기화·관리자 검증용 이력이 필요하면 서버 API 필요
  - 단말 내 조회만이면 현재 로컬 방식 유지 가능

■ 서버 API 제공 시 앱 연동 희망 스펙 (제안)
  - GET /api/member/sessions/{sessionId}/ema — EMA 응답 조회
  - GET /api/member/sessions/{sessionId}/prediction — 예측 결과 조회
  - 또는 GET /api/member/history/ema, /history/prediction (기간·페이징)

■ 정리
  - 260716 수정의견의 「이전 응답·이전 분석결과 확인」은 앱 로컬 히스토리로 구현되어 있음
  - 서버 백업·동기화가 필요한지 여부를 알려주시면 범위 판단·연동 일정 협의 가능
